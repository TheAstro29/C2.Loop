# C2 LOOP

ระบบคลังอุปกรณ์ภายในของ **C2 Tech Company Limited (บริษัท ซีทูเทค จำกัด)** สำหรับติดตามสต๊อก การเบิก/คืน และประวัติของอุปกรณ์ที่บริษัทนำเข้าและจำหน่าย ใช้งานได้ทั้งบนคอมพิวเตอร์และมือถือ (ติดตั้งเป็นแอปบนหน้าจอโฮมได้)

> ระบบนี้ใช้ภายในองค์กร ต้องล็อกอินด้วยบัญชีที่ผู้ดูแลสร้างให้

## ฟีเจอร์หลัก

- **Dashboard** — ภาพรวมสต๊อก สถานะอุปกรณ์ และตัวเตือนของใกล้หมด
- **คลังอุปกรณ์** — MoisturLyzer, Gateway, SimCard, Panolyzer, Color Sorter และอะไหล่ (Color Sorter / Panolyzer) พร้อมตัวกรองและค้นหา S/N
- **เบิกอุปกรณ์** — สร้างรายการเบิกหลายชิ้น ออกใบเบิก (พิมพ์ได้) ทำงานต่อได้แม้ออฟไลน์ แล้วซิงค์เมื่อมีสัญญาณ
- **อนุมัติการเบิก** — ผู้อนุมัติตรวจสอบและอนุมัติ/ปฏิเสธคำขอ
- **ย้าย/เคลม และรอเคลมจาก Supplier** — ติดตามอุปกรณ์ที่ย้าย ส่งเคลม หรือตัดจำหน่าย
- **จัดการ Stock/อะไหล่** (Admin) — เพิ่มสต๊อกแบบตัวช่วย 3 ขั้น (เลือกประเภท → กรอกข้อมูล → ตรวจสอบ), เติมของอะไหล่, Activate ซิมหลายรายการพร้อมกัน, ดูประวัติ Stock
- **ประวัติการเบิก/คืน** — ค้นย้อนหลังได้ทั้งหมด
- **จัดการผู้ใช้งาน** (Admin) — สร้าง/แก้ไขบัญชีและสิทธิ์
- ข้อมูลอัปเดตแบบเรียลไทม์ผ่าน Firestore ไม่ต้องรีเฟรชหน้า

## เทคโนโลยี

| ส่วน | ใช้อะไร |
|---|---|
| Frontend | HTML / CSS / JavaScript ล้วน (ไม่มี build step), ฟอนต์ Chakra Petch, Font Awesome |
| Backend | Firebase Cloud Functions (region `asia-southeast1`) |
| ฐานข้อมูล | Cloud Firestore |
| ไฟล์รูป | Firebase Storage |
| การเข้าสู่ระบบ | Firebase Authentication (custom token) |
| PWA | `manifest.json` + `sw.js` (ติดตั้งเป็นแอปได้) |

## โครงสร้างโปรเจกต์

```
C2-Loop/                  ← frontend (repo นี้)
├─ index.html             โครงหน้าเว็บ
├─ script.js              ตรรกะทั้งหมดของแอป
├─ style.css              สไตล์ทั้งหมด
├─ manifest.json, sw.js   ติดตั้งเป็นแอป (PWA)
├─ vendor/                ไลบรารีที่เก็บไว้ในโปรเจกต์ (Chart.js)
└─ assets/                โลโก้และรูปภาพ

c2-loop-firebase/         ← backend (แยกโฟลเดอร์/repo)
├─ functions/index.js     Cloud Functions
├─ firestore.rules        กฎความปลอดภัยของ Firestore
└─ storage.rules          กฎความปลอดภัยของ Storage
```

## การอัปเดตและ Deploy

**Frontend** (`index.html`, `script.js`, `style.css`)
แก้ไฟล์แล้ว commit/push ขึ้นเว็บโฮสต์ที่ใช้งานอยู่ ไม่ต้อง build ผู้ใช้จะเห็นของใหม่เมื่อรีเฟรชหน้า (ถ้ายังเห็นของเดิม ให้รีเฟรชแบบล้างแคช `Ctrl + Shift + R`)

**Backend** (Cloud Functions)
แก้ที่ `functions/index.js` แล้ว deploy จากโฟลเดอร์ backend:

```bash
firebase deploy --only functions
```

การแก้ไฟล์เฉยๆ ไม่มีผลกับระบบจริงจนกว่าจะ deploy

## การรันทดสอบในเครื่อง

เปิด `index.html` ผ่านเซิร์ฟเวอร์ภายในเครื่อง (เช่น `npx serve` หรือ Live Server ใน VS Code) ระบบจะเชื่อมกับโปรเจกต์ Firebase จริง จึงควรทดสอบด้วยบัญชีทดสอบและระวังไม่ให้ข้อมูลจริงเสียหาย

## สิทธิ์การใช้งาน

| บทบาท | ทำอะไรได้ |
|---|---|
| ผู้ใช้ทั่วไป | ดูคลัง ส่งคำขอเบิก/คืน ดูประวัติ |
